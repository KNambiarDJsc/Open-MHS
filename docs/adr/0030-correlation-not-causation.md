# ADR-0030: Correlation is deterministic and says why; it never asserts cause

- Status: Accepted (reviewed 2026-11-15/16)
- Date: 2026-11-15
- Builds on: [ADR-0022](0022-insights-from-the-journal.md)

## Decision

1. Incident grouping and timelines are produced by **deterministic, versioned rules**. The same events and rule
   version give the same incidents, byte for byte.
2. Every membership edge records its **basis**: `id_match` (same task/goal/trace id, exact), `window` (same robot,
   within a stated time window after clock uncertainty, inferred), `operator` (a person linked it), or `hypothesis`
   (generated by a model, never shown as fact).
3. The engine's vocabulary is temporal and structural (`preceded`, `during`, `same task`, `changed since last
   success`). It has **no causal verb**. A cause is an annotation by a person, recorded with author and provenance.
4. Similarity search (v1) is facet and fingerprint matching (failure category, component, fault code, task type,
   deployment diff), explainable field by field. Embedding search may come later as an optional, labelled hypothesis
   source.
5. AI-generated summaries, if any, are stored as `provenance: generated`, cite the event ids they used, and are never
   the input to statistics.

## Alternatives considered

- **Probabilistic root-cause inference** (Bayesian networks, causal discovery): needs interventions or strong priors
  the data does not contain; produces confident-looking guesses. Rejected for the core.
- **LLM-first triage** (as Roboto and Foxglove now sell): integrate with theirs instead.

## Consequences

- Reports can say "incident 41 contains 7 events; 5 joined by goal id, 2 by a ±250 ms window on robot-12".
- Users get fewer "answers" and more checkable evidence. Whether they value that is a product risk (critical review).

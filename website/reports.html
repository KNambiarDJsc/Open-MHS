Release blockers

  1. Nothing has run on Linux or macOS. Only the Windows build was made.
  2. CI has not run on the M10 work. Two new CI jobs have never executed.
  3. Owner actions: private vulnerability reporting, code-of-conduct contact, PyPI trusted publisher, GitHub Pages, repository settings.
  4. The demo video is not rendered.
  5. The openmhs name on PyPI was free on 2026-10-25; that can change.
  6. crates.io is blocked: openmhs-types embeds files from spec/, which a published crate cannot reach.

Experiments: OctoPrint and ESP32

Experiment 01: read-only OctoPrint adapter

A read-only adapter for OctoPrint, the 3D-printer server, tested against a real OctoPrint 1.11.8 driving its Virtual Printer plugin. Simulated peer only; no physical printer. Full report.

CheckResult
Adapter5 capabilities, 2 request paths, GET only, standard library only
Adapter testspass 42 run, 41 passed, 1 skipped (abstract base), 0 failed
ConformancePASS L1 reached, declared L1, 34 pass, 0 fail, 0 untested
End-to-end demo11 steps, exit 0, 17 requests, all GET

What the real OctoPrint showed that its documentation did not: right after the printer connects, temperature fields are missing and then null before real numbers; an unplugged printer is a 409 on one endpoint but a 200 on another. The adapter now reports these honestly instead of serving a stale or malformed value.

Experiment 02: ESP32 over MQTT, in QEMU

Real ESP-IDF firmware for an ESP32 node, run in Espressif's QEMU beside a real Mosquitto broker, driven through the stock MQTT adapter with state-changing commands. Simulated only; no physical ESP32. Full report.

Tests: 18 passed of 18. Demo: 10 steps, audit chain verified (53 records). The key finding: a node that stops answering may still apply the command later. That is exactly what UNKNOWN_OUTCOME is for, and why the gateway never retries: a retried pulse would have run twice.

Known limitations

The single list is docs/limitations.md. The main points:

  • Not a safety system. A stop is a command, not a safety function. Emergency stops and interlocks belong to the hardware.
  • No physical hardware tested. Passing against a simulator shows the contract and adapter agree, not that a real device works. The hardware guides are unverified.
  • OPC UA is read-only, ROS 2 observation-only, and neither has a committed report. No Modbus RTU.
  • Twin preflight has no physics. Plans run steps in order; there are no parallel steps.
  • MCP is stdio only: no HTTP transport, resources or approval notifications.
  • Single-user trust boundary. Any process running as your OS user can read the operator token. The adapter host has no OS sandbox.
  • No signed descriptors or signed audit export. Rate and slew history, and simulator state, reset on restart.
